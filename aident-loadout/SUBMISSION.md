## Operator-owned review evidence

Before submission, the operator must attach evidence that cannot be safely committed to source control:

1. A reviewer account whose credentials work without MFA, SMS, email confirmation, or private-network access. Provision or rotate it with `OPENAI_PLUGIN_REVIEWER_EMAIL` and `OPENAI_PLUGIN_REVIEWER_PASSWORD` in the operator's local environment and `pnpm script apps/web/scripts/loadout/provision-openai-plugin-reviewer.ts --acknowledge-production-write`. Connect only reviewer-owned QA services and never commit the credentials.
2. A demo-recording URL showing authentication, Action search, schema inspection, connection recovery, preflight, acknowledgement, and terminal execution across every supported platform claimed in the submission.
3. The exact domain-verification token generated by the OpenAI portal, configured in production as `OPENAI_APPS_CHALLENGE_TOKEN`.
4. Current Scan Tools success for the production endpoint.
5. Provider-authorization evidence showing that every enabled integration uses an authorized API and user consent and permits the intermediary access model.
